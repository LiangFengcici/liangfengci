# 从"只有我自己能打开"到"人人可访问"——牙科平台公网部署教程

> 本教程记录本项目（牙科诊所诊疗信息平台）从本机运行到公网部署的完整过程，
> 适合任何 Flask + SQLite 项目复用。写于 2026-11-21。

---

## 一、问题：为什么一开始别人打不开？

网站最初跑在我的电脑上（Flask 监听 `0.0.0.0:8000`），但别的设备访问不到，原因有三层：

| 原因 | 说明 |
| --- | --- |
| 127.0.0.1 是回环地址 | 每台设备的 127.0.0.1 都指"它自己"，手机上访问 127.0.0.1:8000 访问的是手机，不是电脑 |
| 没有公网 IP | 家宽/校园网普遍在运营商 NAT 之后。本项目环境更极端——本机 IP 是 `100.65.x.x`（100.64/10 运营商大内网段），连端口映射（公网 IP + 路由器转发）都做不了 |
| 防火墙 | Windows 默认拦截 8000 端口入站（可放行，但前两条不解决也没用） |

**结论：本地程序要被公网访问，只有两条路——内网穿透（隧道）或云部署。**

## 二、两条路线的对比

### 路线 A：内网穿透（隧道）—— 临时演示用

原理：本机主动向一台"有公网 IP 的中转服务器"发起**出站** SSH/长连接（出站不需要公网 IP），
中转服务器收到外部请求后，通过这条隧道把请求转回本机：

```
用户浏览器 → 中转服务器(公网) ⇄ SSH隧道 ⇄ 我电脑的 8000 端口
```

工具与命令（本项目中试过的）：

```bash
# localhost.run：免注册，一行命令得到临时 https 地址
ssh -R 80:127.0.0.1:8000 nokey@localhost.run

# ngrok：需注册（免费），但可领取"静态域名"，地址永久不变
ngrok config add-authtoken <你的token>
ngrok http 8000 --url https://你领的域名.ngrok-free.app
```

缺点：**电脑必须一直开着**——电脑就是服务器，关机即瘫痪。
本项目实测 localhost.run 免费隧道十几分钟掉线一次，掉线就换地址。

### 路线 B：云部署（最终采用）—— 真正的 7×24

把整个系统部署到云服务器上，程序在**别人的服务器**里 24 小时运行，
我电脑只是开发机，关机不影响任何人访问。

本项目选 **PythonAnywhere 免费版**：零成本、自带 HTTPS、免备案、不用装任何运维软件。

## 三、PythonAnywhere 部署实操（10 分钟）

> 准备物：一份打包好的源码 zip（含代码 + 空数据库 + requirements.txt）

### 1. 注册

打开 `https://www.pythonanywhere.com/registration/register/beginner/` 注册。
**用户名即永久网址**（如 `liangfengci` → `https://liangfengci.pythonanywhere.com`），注册后不可改。
注册后去邮箱点确认链接（可能在垃圾邮件里）。

### 2. 上传代码

Files 标签 → Upload a file → 上传 `dental_cloud.zip`。

### 3. 解压 + 装依赖（Bash 控制台）

```bash
unzip ~/dental_cloud.zip -d ~/dental
cd ~/dental/web
mkvirtualenv dentenv --python=python3.10   # 创建虚拟环境
pip install -r requirements.txt            # 装 flask 等
```

### 4. 创建 Web 应用

Web 标签 → Add a new web app →（跳过付费推广点 Continue）→ **Manual configuration**（不要选 Flask 框架选项）→ Python 3.10。

### 5. 配置四处（Web 页面的 Code 区）

**① WSGI 文件**（点链接进编辑器，全删替换，注意改成自己的用户名）：

```python
import os
import sys

sys.path.insert(0, "/home/liangfengci/dental/web")
os.environ.setdefault("DENTAL_NO_JOBS", "1")   # 云端禁用本地定时任务线程

from app import app as application
```

**② Working directory**：`/home/liangfengci/dental/web`
**③ Virtualenv**：`/home/liangfengci/.virtualenvs/dentenv`
**④ Static files 映射**：URL 填 `/static/`，Directory 填 `/home/liangfengci/dental/web/static`

最后点顶部绿色 **Reload**。访问 `https://用户名.pythonanywhere.com/login` 验证。

### 6. 小程序/客户端接入

把接口基地址写进小程序配置（本项目 `miniprogram/utils/config.js`）：

```js
const ENV = 'prod'
const PROD_URL = 'https://liangfengci.pythonanywhere.com'
```

注意事项：
- 云端是 https 且域名正经，微信开发者工具与真机「打开调试」状态下都能直接请求
- 正式发布（非体验版）需在微信公众平台配置 request 合法域名；体验版演示用「打开调试」绕过即可

## 四、踩过的坑（重要）

1. **浏览器自动翻译会毁掉一切**：Google 翻译把 Bash 控制台里的 `home` 翻成「首页」，
   导致粘贴的命令路径错误、文件列表显示成「梁凤慈_/」。**操作前先右键 → 恢复成原始网页。**
2. **数据要"快照式"打包**：SQLite 直接复制 zip 可能在 WAL 模式下损坏，
   应该用 Python `sqlite3.backup()` 生成一致性快照再打包。
3. **种子排班只有 7 天**：演示数据里的号源（slot）只生成到部署当天，第二天小程序就"约不到医生"。
   解决：写幂等脚本按同一模板往后补 60 天班次（本项目 `web/extend_schedule.py`，本地和云端各跑一次）。
4. **免费版每 3 个月要点一次续期**：Web 页面顶部会有黄色提醒，点一下 Run 即可，邮箱也会通知。

## 五、最终效果

| | 隧道方案（此前） | 云部署（现在） |
| --- | --- | --- |
| 电脑开机要求 | 必须常开 | 关机照常服务 |
| 网址稳定性 | 免费隧道常掉线/换址 | `https://liangfengci.pythonanywhere.com` 永久固定 |
| 访问者 | 依赖本机进程活着 | 任何人、任何设备、任何时间 |
| 成本 | 0 | 0 |

**架构一句话总结**：出站隧道是"把公网请求骗进你家"，云部署是"把家搬进公网"——
要给老师/客户长期使用，必须选后者。
